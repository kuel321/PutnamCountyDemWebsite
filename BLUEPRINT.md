# Blueprint: Standing up a blank Payload CMS site from `edwardsforputnam@chancecms-template`

This documents exactly what was done to turn the `chancecms-template` branch of
`git@github.com:kuel321/edwardsforputnam.git` into a working, blank Payload CMS
instance in this directory. Keep this around if/when this gets promoted into its
own `PayloadStarter` repo — it's the checklist for repeating (or finishing) the process.

## Background

The `chancecms-template` branch was created (commit `287f68b`, "Create ChanceCMS
reusable template branch") by stripping the Edwards-for-Putnam frontend
(pages, header/footer, blocks, heros, providers, seed data) out of the original
site, intending to leave just the Payload config, collections, admin branding,
and plugins as a reusable starting point.

**The strip was incomplete** — it deleted the `src/blocks/*` and `src/heros/*`
directories and the entire `src/app/(frontend)` route group, but left the
`Pages` and `Posts` collection configs still importing block/hero configs from
those now-deleted paths, and left a stale auto-generated `importMap.js` that
still pointed at deleted `Header`/`Footer` global components. This meant the
admin panel 500'd on every load. Restarting from this branch as-is would not
have produced a working site.

## What was actually run

1. **Cloned the template branch directly into this (empty) directory:**
   ```bash
   git clone -b chancecms-template --single-branch git@github.com:kuel321/edwardsforputnam.git .
   ```

2. **Deleted the committed SQLite database** (`edwardsforputnam.db`, ~1.9MB) —
   it was real site data checked into git by mistake, not an empty starter DB.
   ```bash
   rm edwardsforputnam.db
   ```

3. **Fixed the broken collection configs** left over from the incomplete strip:
   - [src/collections/Pages/index.ts](src/collections/Pages/index.ts) — removed imports of 9 deleted block
     configs (`Archive`, `CallToAction`, `Content`, `FormBlock`, `MediaBlock`,
     `MeetTheCandidate`, `FightingFor`, `Newsletter`, `SocialMedia`) and the
     deleted `hero` field from `@/heros/config`. Replaced the `Hero` tab +
     `layout` blocks field with a single plain `content` richText field, same
     pattern as `Posts`.
   - [src/collections/Posts/index.ts](src/collections/Posts/index.ts) — removed imports of 3 deleted block
     configs (`Banner`, `Code`, `MediaBlock`) and the `BlocksFeature` that
     referenced them in the Lexical editor config.
   - Regenerated the admin import map (this file is auto-generated by Payload
     and had gone stale, still referencing deleted `@/Header/RowLabel` and
     `@/Footer/RowLabel`):
     ```bash
     npm run generate:importmap
     ```

4. **Deleted dead frontend-only files** that were leftover orphans (verified
   with a repo-wide grep that nothing in the live build graph — `payload.config.ts`,
   the collections, or the `(payload)` admin/API route group — imported them):
   - `src/components/RichText` (this was the one still importing the deleted
     blocks — the actual source of the original crash)
   - `src/components/{Card,CollectionArchive,Link,LivePreviewListener,PageRange,Pagination,PayloadRedirects,Logo,Media,ui,AdminBar}`
   - `src/search/Component.tsx` (frontend search UI; `beforeSync.ts` and
     `fieldOverrides.ts` in the same folder are still used by the search plugin
     and were kept)

5. **Added `*.db` / `*.db-journal` to [.gitignore](.gitignore)** so a fresh local
   SQLite database never gets committed again the way `edwardsforputnam.db` was.

6. **Created `.env`** from `.env.example` (this file is gitignored, values below
   are illustrative — generate your own, don't reuse these):
   ```
   DATABASE_URL=file:./putnam-county-dems.db
   PAYLOAD_SECRET=<random 32-byte hex>
   NEXT_PUBLIC_SERVER_URL=http://localhost:3000
   CRON_SECRET=<random 32-byte hex>
   PREVIEW_SECRET=<random 32-byte hex>
   ```
   Generate secrets with:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   Note: `.env.example`'s `DATABASE_URL` comment mentions Mongo/Postgres, but
   this project is wired to SQLite (`@payloadcms/db-sqlite` in
   [src/payload.config.ts](src/payload.config.ts)), so the URL must be a `file:` path, not a connection
   string.

7. **Installed dependencies with `npm install`** (there's an `package-lock.json`
   in the repo, not a `pnpm-lock.yaml`, despite the README/scripts assuming
   pnpm — npm works fine and matches the committed lockfile).

8. **Verified it actually boots:**
   ```bash
   npm run dev
   curl http://localhost:3000/admin   # -> 200, shows "create first user" screen
   curl http://localhost:3000/        # -> 404 (expected: no frontend route exists anymore)
   ```
   The `/admin` 200 with the create-first-user screen confirms Payload
   connected to the (fresh, empty) SQLite database, pulled/pushed schema
   successfully, and rendered the admin UI with no missing-module errors.

## Current state

- Backend-only Payload CMS 3.80 (Next.js 16 App Router + SQLite via libSQL).
- Collections: `Pages`, `Posts`, `Media`, `Categories`, `Users`. Pages/Posts
  are now plain (title + richText content + SEO tab), no layout-builder blocks.
- Plugins wired up: SEO, search, redirects, nested-docs (categories),
  form-builder.
- No frontend route group at all — `/` 404s by design. This is admin+API only.
- Empty database, no admin user created yet (do that via the `/admin`
  first-run screen).

## Known follow-ups before calling this "PayloadStarter"

Left untouched because they weren't blocking anything, but worth doing before
publishing as a generic starter template:

- **Candidate-specific branding still present** — grep hits in:
  [src/components/AdminFooter/index.tsx](src/components/AdminFooter/index.tsx), [src/components/AdminIcon/index.tsx](src/components/AdminIcon/index.tsx),
  [src/components/AdminLogo/index.tsx](src/components/AdminLogo/index.tsx), [src/components/BeforeDashboard/index.tsx](src/components/BeforeDashboard/index.tsx),
  [src/app/(payload)/custom.scss](src/app/\(payload\)/custom.scss), [src/plugins/index.ts](src/plugins/index.ts) (hardcoded
  `"Edwards For Putnam"` in `generateTitle`), [src/utilities/generateMeta.ts](src/utilities/generateMeta.ts),
  [src/utilities/mergeOpenGraph.ts](src/utilities/mergeOpenGraph.ts), and `package.json`'s `name`. Also
  `public/media/chance-logo-no-letters-png.png` is a real logo asset.
- **`npm audit`** currently reports 32 vulnerabilities (1 low / 14 moderate /
  16 high / 1 critical) in transitive deps — worth a look before this becomes
  a template other projects fork from.
- **Smaller orphaned utility files may still exist** — the cleanup above
  removed the clearly-dead component cluster that was breaking the build, but
  files like `src/utilities/{formatAuthors,formatDateTime,getDocument,getGlobals,getMediaUrl,getMeUser,getRedirects,useClickableCard,useDebounce,canUseDOM}.ts`
  were not individually audited for use and may also be frontend leftovers.
- **No admin user exists yet** — first run of `/admin` will prompt to create one.
- Next.js printed a "multiple lockfiles" warning pointing at a
  `C:\Users\LukeShort\package-lock.json` one level up — harmless, but could be
  silenced with `outputFileTracingRoot` in [next.config.ts](next.config.ts) if it's noisy.

## To run it yourself

```bash
npm install
cp .env.example .env   # then fill in DATABASE_URL=file:./<name>.db and generate the three secrets
npm run dev
# open http://localhost:3000/admin and create your first admin user
```
